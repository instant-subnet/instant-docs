Troubleshooting

Start with read-only checks and protect every secret.

The commands below inspect local health and service state. They do not print environment files, wallet contents, or private keys, and they do not restart services or change chain state.

Before sharing any output

Stop if output contains secret material

Never share a mnemonic, seed phrase, private key, wallet file, bearer token, environment file, release signing key, or complete request and response body. Instant support will not ask for them.

  • Review logs locally before copying them.
  • Remove customer content, tokens, request bodies, and response bodies.
  • Keep file ownership and permission information when it helps diagnose a boundary.
  • Use the bounded Miner Kit diagnostics command when available instead of archiving the host.

A hotkey address and UID are public identifiers, but wallet bytes that control the hotkey are never public.

Miner

Check the GPU, backend, and worker in that order

1. Confirm the GPU and driver are visible

nvidia-smi

Look for the expected GPU, a loaded driver, available memory, and no unknown process consuming the model's allocation.

2. Check the local inference backend

curl --fail --silent --show-error http://localhost:8000/health

An empty successful response is normal for vLLM health. A connection failure means the backend must be fixed before the worker can qualify.

3. Run the signed Miner Kit preflight

sudo runuser --user instant-miner -- \
  /opt/instant-miner/current/bin/instant-miner-kit preflight \
  --config /etc/instant-miner/worker.env

This checks configuration, wallet ownership, GPU, model, backend, and platform reachability without printing secret values.

4. Inspect service state

sudo systemctl status --no-pager instant-worker.service

Check whether the service is active, its last exit status, and whether it is restarting repeatedly.

5. Read a bounded log tail

sudo journalctl -u instant-worker.service -n 100 --no-pager

Review the output locally. Logs are not guaranteed to redact application data and should not be pasted directly into a support channel.

Worker connection

Connected is not the same as routable

Common worker states
SymptomLikely boundarySafe next check
Cannot connectDNS, TLS, clock, gateway URL, or platform identity mismatch.Confirm system time and outbound HTTPS access; then run the signed Miner Kit preflight above.
Connected, not readyBackend health, model digest, capacity, or heartbeat qualification.Check local backend health and the bounded worker log tail.
Ready, no ordinary trafficThe worker may be canary-only or on a temporary platform hold after verification.Open the public miner profile and review its latest TOPLOC status with the platform operator.
Identity rejectedThe submitted Finney/SN46 UID and hotkey do not map to one another, or the signature failed.Confirm both public values and that the selected local wallet controls the submitted hotkey.
Receipt rejectedRequest binding, response binding, token counts, sequence, or signing identity failed.Preserve the request ID and bounded error code; do not resend customer content.

Validator

Check the configured weight mode

Service is offline or restarting

pm2 status instant-validator

Confirm the private .env, wallet path, platform report URL, Finney, and netuid 46 settings.

Read a bounded log tail

pm2 logs instant-validator --lines 100 --nostream

Separate burn writes, report validation, score calculation, wallet, and Finney connection errors.

The burn vector was not submitted

Confirm the finalized chain is in Burn mode with commit/reveal disabled, the wallet is correct, and the explicit Finney write gate is enabled. Do not enable scoring as a workaround.

Report scoring did not produce a vector

Check for a stale, duplicate, wrongly signed, wrong-network, or empty report. The validator rejects invalid reports instead of guessing weights.

Do not change modes to bypass an error

Fix the reported chain, wallet, or report condition. Burn and report scoring are separate operating modes, not recovery mechanisms.

Create a bounded support bundle

After the signed Miner Kit is installed, use its redacting diagnostics command:

sudo /opt/instant-miner/current/bin/instant-miner-kit diagnostics \
  --config /etc/instant-miner/worker.env > instant-diagnostics.json

Before sharing the file:

  1. Open it locally and confirm no secret or customer content is present.
  2. Include the approximate failure time and the public request ID, if one exists.
  3. State whether the failure is installer, backend, connection, routing, receipt, proof, chain, or scoring related.
  4. Do not attach wallet files, environment files, database files, or unrestricted journal archives.
