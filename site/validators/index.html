Validator guide

Run a small, supervised weight service.

An Instant validator runs one PM2-managed loop on Finney subnet 46. Its default weight plan is a 100% burn vote to the current subnet-owner UID.

Burn is the default

The checked-in configuration enables burn and disables chain writes. Report scoring and weight submission require explicit private configuration.

Prerequisites

  • A Linux host with reliable time, storage, and outbound HTTPS/Finney access.
  • An operational validator hotkey registered on Finney subnet 46 with the required permit and stake.
  • The reviewed Instant validator release and its pinned dependencies.
  • For report scoring, the expected platform report URL and signer identity.
  • A private .env containing wallet and service configuration.

Use an operational hotkey only

The validator host does not need the owner's mnemonic, seed phrase, or private coldkey.

One supervised process

Configure once and let PM2 run the loop

  1. Create private configuration

    cp .env.example .env

    Set the validator wallet, platform report URL, schedule, Finney, and netuid 46.

  2. Start the service

    pm2 start ecosystem.config.cjs

    PM2 supervises one non-interactive validator process.

  3. Inspect bounded status

    pm2 status instant-validator

    Confirm the service is online and not restarting before inspecting its bounded log tail.

  4. Verify the dry run

    Review the resolved owner UID and 100% burn vector before enabling chain writes.

Burn and report-scoring modes are mutually exclusive. Both fail closed on invalid chain or report state. This service does not implement commit/reveal or interactive one-shot commands.

Weight submission

Burn mode is chain-only

  1. Read one finalized chain snapshot.
  2. Require protocol Burn mode with commit/reveal disabled.
  3. Resolve the subnet-owner hotkey, UID, and weight version from that snapshot.
  4. Submit the owner UID with weight 65,535 when chain writes are enabled.
  5. Wait for the next configured cycle.

Report-scoring mode instead verifies one signed, completed-period platform report and applies the documented deterministic formula. The platform owns miner registration checks and supplies each miner's UID and hotkey.

Current limitations

  • Report-scoring mode trusts the platform's signed miner roster and metrics.
  • It does not query or probe miners directly.
  • Invalid, stale, duplicate, wrongly signed, wrong-network, or empty reports never reach the scoring writer.
  • There is one scoring formula and one direct writer path.
  • Burn and report scoring cannot run in the same process.
  • Commit/reveal is not supported.
