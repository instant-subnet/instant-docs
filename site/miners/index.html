Miner guide

Connect GPU capacity without opening an inbound service.

An Instant worker connects outbound to the platform, authenticates with a submitted SN46 UID and chain-registered hotkey, serves the approved model locally, and emits TOPLOC evidence for asynchronous verification.

Quick start

Register, install, and provide two public identifiers

  1. Register an operational Miner hotkey on SN46.
  2. Run the official installer on the GPU host.
  3. Enter the registered Miner UID.
  4. Enter the registered SS58 hotkey.
  5. Wait for the installer to report that the model, worker, and Platform connection are ready.
curl -fsSL https://instantsubnet.com/miner/install | sudo bash

The installer searches the invoking user's and root's standard Bittensor wallet directories for the matching operational hotkey. If it cannot find exactly one match, it asks for the hotkey file's exact path and verifies that it resolves to the SS58 address entered above.

Advanced setup

Provide setup values for repeat installations

Operators installing more than one host may provide the public UID, public SS58 hotkey, and operational hotkey file path without answering the installer prompts: 

curl -fsSL https://instantsubnet.com/miner/install | sudo env \
  INSTANT_SETUP_UID=MINER_UID \
  INSTANT_SETUP_HOTKEY=MINER_SS58_HOTKEY \
  INSTANT_SETUP_HOTKEY_PATH=/path/to/wallet/hotkeys/HOTKEY_NAME \
  bash

INSTANT_SETUP_HOTKEY_PATH is optional when the installer can uniquely discover the matching hotkey. Advanced wallet layouts may instead set INSTANT_SETUP_WALLET_PATH together with both INSTANT_SETUP_WALLET_NAME and INSTANT_SETUP_WALLET_HOTKEY.

These values identify an already-registered operational hotkey. Never put a seed phrase, mnemonic, private coldkey, or wallet password in an environment variable or installer command.

Prerequisites

  • Exactly one visible NVIDIA GPU with at least 31,744 MiB VRAM, compute capability 8.0+, and driver 570+.
  • Ubuntu 22.04 or 24.04 on x86-64.
  • At least 80 GiB free on the model filesystem.
  • Outbound DNS, HTTPS, and secure WebSocket access on port 443.
  • An operational Bittensor hotkey already registered on the intended network and subnet.
  • Administrator access for the signed package installation and system service setup.

Hardware support is release-specific. Do not assume that a GPU is accepted from VRAM capacity alone; driver, model, engine, tokenizer, and proof-profile compatibility are checked separately.

Chain identity

Enter both UID and hotkey; the platform verifies the pair

Hotkey

The miner's public operational identity. Its local signer proves control during onboarding and signs worker receipts.

UID

The current numerical SN46 slot used for weights. The miner submits it and the platform verifies that it maps to the submitted hotkey.

GPU

Serving capacity attached to an authenticated worker session. A GPU has no network UID by itself.

  1. Register the operational hotkey on SN46.
  2. Enter its current UID and hotkey during installation.
  3. If automatic discovery fails, enter the exact operational hotkey file path.
  4. Sign the platform's one-use WSS challenge locally.
  5. The platform verifies the UID/hotkey mapping and runs a TOPLOC canary.
  6. Ordinary routing starts after the canary passes.

UID assignments can change after deregistration or chain changes. The platform refreshes the submitted pair before publishing validator metrics.

SSH and localhost

Use the CLI or the local operations page

All SSH commands use the installed Miner Kit binary:

MINER_CLI=/opt/instant-miner/current/bin/instant-miner-kit

sudo "$MINER_CLI" status
sudo "$MINER_CLI" status --json
sudo "$MINER_CLI" stats --period 24h
sudo "$MINER_CLI" stats --json --period 7d
sudo "$MINER_CLI" logs --service worker --lines 200
sudo "$MINER_CLI" logs --service vllm --lines 200
sudo "$MINER_CLI" service restart worker
sudo "$MINER_CLI" service restart vllm
sudo "$MINER_CLI" service restart all
sudo "$MINER_CLI" diagnostics

The CLI reports Platform connection and routing readiness; worker, vLLM, and TOPLOC readiness; release, model, profile, and GPU health; request and token totals; TTFT, generation TPS, proof outcomes, and sanitized errors.

The same data and allow-listed actions are available at 127.0.0.1:8787. From an SSH-only computer:

ssh -L 8787:127.0.0.1:8787 root@MINER_HOST

Keep that tunnel open and visit http://127.0.0.1:8787. The page is not exposed publicly.

Release management

Updates are manual

MINER_CLI=/opt/instant-miner/current/bin/instant-miner-kit

sudo "$MINER_CLI" update check
sudo "$MINER_CLI" update apply
sudo "$MINER_CLI" rollback

update check reads the release metadata referenced by GitHub main. update apply downloads that signed archive, authenticates it with the installed release key, stages and activates it, verifies readiness, and retains the previous signed release for rollback. Miner Kit never auto-updates and never copies loose Python files to a host.

Important limits

  • A valid registration is not enough: the first inference/TOPLOC canary must pass before customer routing.
  • Instant does not set a default completion limit. Without a customer-supplied limit, generation continues until the model stops or the remaining 131,072-token combined context is exhausted.
  • The supported release uses one capability-based NVIDIA/model/backend profile, not a product-name allowlist.
  • Meeting the static GPU floor makes a host a candidate; each GPU family must pass an inference and TOPLOC canary before routing.
  • Self-reported GPU and capacity data are advisory. Platform-observed health and TOPLOC outcomes control routing.
  • A signed receipt proves who committed to the delivered bytes; it does not prove which model generated them.
  • A failed, missing, or expired verification may cause the platform to place the miner on temporary hold for review.

Wallet and host safety

Never provide a coldkey or recovery secret

The miner needs an operational hotkey signer. If it cannot discover that signer, it asks for the exact hotkey file path. It never needs the owner's private coldkey, mnemonic, seed phrase, or a copy of another validator's wallet.

  • Run only the command published on this documentation page.
  • Confirm the installer reports a pinned release before approving changes.
  • Keep the inference backend on loopback and the worker connection outbound-only.
  • Review diagnostic output before sharing it with support.
