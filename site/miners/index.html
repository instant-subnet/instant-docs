Miner guide

Connect GPU capacity without opening an inbound service.

An Instant worker connects outbound to the platform, authenticates with a submitted Finney/SN46 UID and chain-registered hotkey, serves the approved model locally, and emits TOPLOC evidence for asynchronous verification.

The public installer is unavailable

Instant does not currently provide a public installation command. Do not run installer commands shared through unofficial channels.

Prerequisites

  • Exactly one visible NVIDIA GPU with at least 31,744 MiB VRAM, compute capability 8.0+, and driver 570+.
  • Enough host RAM and disk for the approved GPT-OSS-20B model and serving engine.
  • A clean Linux host compatible with the signed Miner Kit release.
  • Outbound DNS, HTTPS, and secure WebSocket access on port 443.
  • An operational Bittensor hotkey already registered on the intended network and subnet.
  • Administrator access for the signed package installation and system service setup.

Hardware support is release-specific. Do not assume that a GPU is accepted from VRAM capacity alone; driver, model, engine, tokenizer, and proof-profile compatibility are checked separately.

Installation

Public access unavailable

Miner onboarding is not open to the public. Public installation is not supported.

Chain identity

Enter both UID and hotkey; the platform verifies the pair

Hotkey

The miner's public operational identity. Its local signer proves control during onboarding and signs worker receipts.

UID

The current numerical SN46 slot used for weights. The miner submits it and the platform verifies that it maps to the submitted hotkey.

GPU

Serving capacity attached to an authenticated worker session. A GPU has no network UID by itself.

  1. Register the operational hotkey on Finney subnet 46.
  2. Enter its current UID and hotkey during installation.
  3. Sign the platform's one-use WSS challenge locally.
  4. The platform verifies the UID/hotkey mapping and runs a TOPLOC canary.
  5. Ordinary routing starts after the canary passes.

UID assignments can change after deregistration or chain changes. The platform refreshes the submitted pair before publishing validator metrics.

Important limits

  • A valid registration is not enough: the first inference/TOPLOC canary must pass before customer routing.
  • The supported release uses one capability-based NVIDIA/model/backend profile, not a product-name allowlist.
  • Meeting the static GPU floor makes a host a candidate; each GPU family must pass an inference and TOPLOC canary before routing.
  • Self-reported GPU and capacity data are advisory. Platform-observed health and TOPLOC outcomes control routing.
  • A signed receipt proves who committed to the delivered bytes; it does not prove which model generated them.
  • A failed, missing, or expired verification may cause the platform to place the miner on temporary hold for review.

Wallet and host safety

Never provide a coldkey or recovery secret

The miner needs an operational hotkey signer. It never needs the owner's private coldkey, mnemonic, seed phrase, or a copy of another validator's wallet.

  • Run only the command published on this documentation page.
  • Confirm the installer reports a pinned release before approving changes.
  • Keep the inference backend on loopback and the worker connection outbound-only.
  • Review diagnostic output before sharing it with support.
